# adds Provider

ADDS is an Active Directory Domain Services provider that manages directory objects and policy through PowerShell 7 commands on remote Windows systems over WinRM or SSH.

## Requirements

- PowerShell 7 (`pwsh`) on the target host. The provider may run on Windows Powershell, but all tests are conducted on PowerShell 7.
- The `ActiveDirectory` and `GroupPolicy` PowerShell module on the target host.
- WinRM (http or HTTPS on default ports 5985 or 5986, respectively) or OpenSSH (port 22) reachable from wherever Terraform runs

## Example Usage

```terraform
terraform {
  required_providers {
    adds = {
      source = "bjoernf73/adds"
    }
  }
}

# WinRM with NTLM authentication.
provider "adds" {
  transport       = "winrm"
  host            = "dc1.contoso.local"
  username        = "CONTOSO\\terraform"
  password        = var.password
  winrm_auth      = "ntlm"
  powershell_path = "pwsh"
}

# SSH with password authentication.
provider "adds" {
  alias           = "ssh"
  transport       = "ssh"
  host            = "dc1.contoso.local"
  username        = "terraform"
  password        = var.password
  powershell_path = "pwsh"
}
```

## Authentication

| Transport | Mechanisms |
| --- | --- |
| `winrm` | `basic`, `ntlm`, `kerberos` |
| `ssh` | password, private key |

Within a domain, WinRM over HTTP with Kerberos is a common configuration; WinRM encrypts session traffic after authentication. Basic authentication does not encrypt traffic, so use HTTPS with Basic. For Terraform runners outside a trusted domain network, prefer WinRM over HTTPS or SSH.

This provider does not retrieve credentials or SSH keys from secret stores such as HashiCorp Vault or Azure Key Vault. Use the relevant Terraform provider or secret-management workflow to supply those values to your configuration.
