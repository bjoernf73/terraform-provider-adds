# v0.0.27

Reads no longer load the PowerShell `ActiveDirectory` or `GroupPolicy` modules — they run
directly over LDAP. Because the provider executes every operation in a fresh remote process,
that module import (~650 ms) was paid again on *every* read; removing it makes `plan` and
refresh dramatically faster on large configurations, especially over higher-latency links.
Behaviour is unchanged: each migrated read was validated field-for-field against the module
it replaces on a live domain controller.

## Changed

- **Reads now use LDAP (`System.DirectoryServices.Protocols`) instead of the PowerShell AD
  modules.** This covers the per-plan refresh path for every object type:
  - resource reads for `adds_organizational_unit`, `adds_group`, `adds_user`, `adds_computer`,
    and the `adds_domain` data source;
  - the version-drift check for `adds_backup_gpo` and `adds_json_gpo`, which previously loaded
    the `GroupPolicy` module on every plan — it now reads the GPO's `versionNumber` attribute
    and `GPT.ini` directly.

  No configuration change is required and no attribute values change. A read now opens a
  lightweight LDAP connection on the target host (as the already-connected account) instead of
  importing a module, so there is nothing to opt into or out of.
- **`gpo_powershell_path` now affects only Group Policy *imports*, not reads.** GPO reads are
  module-free, so they no longer depend on native Windows PowerShell; the setting still routes
  `adds_backup_gpo`/`adds_json_gpo` *imports* (which use `Import-GPO`) to `powershell.exe`.

## Fixed 

- **`adds_json_gpo`: a permanent `computer_sysvol_version` / `user_sysvol_version` diff could
  appear after create.** The create path reported the SYSVOL version from the `GroupPolicy`
  module, which reads a stale `0` immediately after `New-GPO`, while the new LDAP read parses
  `GPT.ini` directly — so every subsequent plan showed e.g. `0 -> 17`. Both paths now read the
  SYSVOL version from `GPT.ini`. The GPO's `GPT.ini` is also written clean (`[General]` plus the
  packed `Version` only), dropping the cosmetic `displayName` line `New-GPO` leaves behind and
  keeping the SYSVOL version in lockstep with the AD `versionNumber` (`Version = userVersion *
  65536 + computerVersion`).
- **SSH transport: every operation failed with *"cannot determine a domain controller to bind
  to"***. The new LDAP code derived the domain from `USERDNSDOMAIN`, which Windows populates
  under WinRM but **not** in a Win32-OpenSSH exec session. The target domain is now resolved
  from the host's own domain membership (`Domain.GetComputerDomain()`, falling back to the
  local network configuration), independent of any environment variable. WinRM was unaffected.
- **Clearer error when a remote operation returns no JSON.** Previously a bare *"remote
  PowerShell returned no JSON output"*; it now includes the remote exit code and stderr, so the
  real cause (a module warning, a permissions error, or a WinRM shell recycled under its memory
  quota) is visible.

## Internal

- Each LDAP read ships with a host-gated parity test (`internal/ad/*_ldap_live_test.go`) that
  diffs it field-for-field against the PowerShell module on a live DC; they skip without
  `ADDS_HOST`.
- Reusable LDAP helpers added to `internal/ad/scripts/common.ps1` (connection, SID/GUID/
  multi-value decoders, security-descriptor and ACL checks, principal resolver, UAC decode),
  and a `moduleFreeOperations` allowlist in `internal/ad/scripts.go` that controls which
  operations skip the module import.
- Showcase gained a per-system module (`test/showcase/modules/system`) invoked for several
  short names, so the suite exercises the provider at the scale a real directory reaches.
