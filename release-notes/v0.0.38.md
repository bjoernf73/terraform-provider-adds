# v0.0.38

Adds an ACL export data source for lifting an existing domain's delegation into Terraform.

## Added

- **`adds_acl_export` — export existing ACLs as `adds_acl` configuration.** Reads the explicit
  (non-inherited) access control entries of one object, or every object below a path, and renders
  ready-to-use `adds_acl` blocks. Built for onboarding a domain whose delegation is too extensive to
  recreate by hand: inherited ACEs are ignored, the **Protect from accidental deletion** ACE is
  excluded, SIDs and GUIDs are resolved to names, and each object's `inheritance_blocked` state is
  captured so the whole configuration can be replicated. The rendered config is exposed as `hcl`
  (pair it with the `local_file` resource or `terraform output` to write a `.tf` file); the same
  data is also available structured in `objects`. `target` uses the portable form (a slash path for
  OUs, otherwise a relative distinguished name), so an export replays against another domain with
  the same relative structure. Select the scope with `path` (default `""` = domain root),
  `recursive`, and `object_types` (filter by Active Directory structural class name, for example
  `["organizationalUnit", "container", "user"]`). The search is paged, so a whole-domain export is
  not truncated by the server's size limit.

- **`adds_domain` now exposes the naming-context distinguished names** `domain_path`,
  `configuration_path` and `schema_path`, so they can be passed straight to `adds_acl_export`'s
  `path` (or anywhere a naming-context DN is needed).

## Fixed

- **`adds_gpo_link`, `adds_acl` and `adds_acl_export` no longer fail under PowerShell 7.6.9 with
  "Argument types do not match".** Those scripts built result collections with
  `New-Object System.Collections.Generic.List[object]`, which PowerShell 7.6 returns adapter-wrapped
  so that the `@(...)` array operator throws when the list is later converted. Constructing the lists
  with `[System.Collections.Generic.List[object]]::new()` avoids the wrapper. `adds_gpo_link` failed
  on every create (in `ConvertTo-ADDSGPLinkString`) regardless of `order`; the authoritative-ACL
  scripts shared the same latent fault. The group-scope preflight was hardened the same way.
