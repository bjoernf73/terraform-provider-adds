# v0.0.29

`adds_gpo_links` now manages GPO links entirely over LDAP instead of the PowerShell
`GroupPolicy` module, removing the PowerShell-edition sensitivity that made it fail under `pwsh`.
The client also retries a remote operation that returns no output, closing a gap where a lost
WinRM response surfaced as a hard "no JSON output" error.

## Fixed

- **`adds_gpo_links` no longer depends on the `GroupPolicy` PowerShell module.** It was the last
  resource using `Get-GPInheritance` / `New-GPLink` / `Set-GPLink`, and that module is not native
  to PowerShell 7: under `pwsh` it loads through the Windows PowerShell compatibility session and
  returns **deserialized** objects whose `GpoId` is null, so every link operation failed with
  *"You cannot call a method on a null-valued expression."* The read, create/update and delete now
  operate directly on the target's `gPLink` and `gPOptions` attributes over LDAP
  (`System.DirectoryServices.Protocols`), so they work identically under `pwsh` and
  `powershell.exe`, no longer depend on `gpo_powershell_path`, and skip the ~650 ms module import.
  No configuration or state changes: the attribute set and import IDs are unchanged.
- **A remote operation that exits 0 with no output is retried instead of failing.** Every
  operation script emits a JSON document on success, so an empty stdout at exit code 0 means the
  WinRM response was lost or truncated. The client now retries such a result up to three times with
  backoff (the scripts are idempotent) before surfacing the *"no JSON output"* error. This
  complements the v0.0.28 transport retries (which covered an empty **stdin** and network faults).

## Internal

- New reusable `Set-ADDSAttribute` LDAP-modify helper in `common.ps1`, and a
  `gpo_link_ldap_common.ps1` with the gPLink parse/build and GPO-resolution helpers. `gpo_link_read`
  / `gpo_link_ensure` / `gpo_link_delete` are now in the `moduleFreeOperations` allowlist (routed to
  `pwsh`, no `ActiveDirectory` import either).
- The older `gpo_link_common.ps1` (GroupPolicy module, `Resolve-GPOIdentity`) is retained because
  `adds_gpo_permission`, `adds_gpo_security_filter` and `adds_gpo_wmi_filter` still use it.
- Host-gated parity test `gpo_link_ldap_live_test.go` diffs the LDAP read against
  `Get-GPInheritance` for the domain root; link **ordering** direction is additionally exercised by
  the showcase's multi-link OUs (a reversed parse would make a re-plan non-idempotent).
- In `gPLink`, the highest-precedence link (GPMC "Link Order" 1) is the **last** entry; the string
  runs from lowest to highest precedence, so the read reverses the parsed entries to assign order
  1..N and the write emits the desired links (first = highest) in reverse.
