# v0.0.37

Renames `adds_access_rule` to `adds_ace`, adds authoritative ACL management, non-authoritative
GPO links and a local (no-remoting) transport, and restores portability of certificate-autoenrollment
GPOs exported and imported through `adds_json_gpo`.

## Added

- **`adds_acl` — authoritative management of an object's DACL.** Declares the complete set of
  explicit ACEs for a target; any explicit, non-inherited ACE that is not declared is removed on
  apply. ACEs are matched by identity rather than position, so Active Directory's own ACE ordering
  never produces a permanent diff. The **Protect object from accidental deletion** ACE (a `Deny`
  for `Everyone` on `Delete`/`DeleteTree`) and inherited ACEs are always preserved and never
  reported as drift. `inheritance_blocked` (default `false`) can break inheritance so only the
  declared ACEs apply, and is re-enabled on destroy only if this resource broke it. Because it owns
  the whole DACL, do not point an `adds_ace` at the same target; `terraform import` an
  existing object first to capture its current ACEs before editing.

- **`adds_gpo_link` — a single, non-authoritative GPO link.** The link counterpart to `adds_ace`:
  it inserts, updates or removes the one link it declares on an OU, domain or site and leaves every
  other link in place, so several independent Terraform configurations can each contribute a link
  to the same target (a base structure plus per-system modules, for example). Precedence is 1-based
  to match GPMC. By default `order` only chooses where a new link is inserted and the link then
  keeps its slot, so links added later by others never cause drift; `monitor_order = true` pins the
  link to `order` and reconciles it back if it moves. Do not point `adds_gpo_links` (authoritative)
  and `adds_gpo_link` at the same target — the former would prune the latter.

- **`transport = "local"` — run without remoting.** The provider can now execute its PowerShell on
  the machine running Terraform itself, under the current Windows logon, with no WinRM or SSH and no
  `host`, `username` or `password`. It is intended for running Terraform directly on a domain
  controller or domain member. The warm-host optimization and GPO routing to Windows PowerShell work
  the same as over a remote transport. On a host without PowerShell 7, set
  `powershell_path = "powershell.exe"` to use Windows PowerShell 5.1.

## Changed

- **`adds_access_rule` has been renamed to `adds_ace`.** The name now matches its unit of work (a
  single ACE) and reads cleanly alongside the new whole-DACL `adds_acl`. `adds_access_rule` is kept
  as a **deprecated alias** so existing configurations and state keep working; it emits a
  deprecation warning and will be removed in a future release. Migrate each resource with
  `terraform state mv adds_access_rule.<name> adds_ace.<name>` and rename the blocks. The schema,
  attributes, import format and behaviour are otherwise unchanged.

## Fixed

- **`adds_json_gpo` now tokenizes the certificate enrollment policy server Id.** Export left the
  source domain's live policy server GUID (e.g. `{D3B2104C-...}`) hard-coded in the registry
  settings, and import never substituted it, so a certificate-autoenrollment GPO moved between
  domains kept pointing at the wrong AD CS deployment. The `####PolicyServerId####` token that the
  reference module (`dry.ad.gpohelper.psm1`) uses was documented but never actually implemented in
  the provider's scripts — only the SID tokenization was ported. Export now replaces the live
  policy server Id with `####PolicyServerId####`, and import resolves the token back to the target
  host's configured policy server, matching the round-trip behaviour of the reference module.
  Export is a no-op when no policy server is configured, and import raises a clear error if the
  token is present but the target has no certificate enrollment policy server.
