# v0.0.26

Re-introduces `gpo_powershell_path` so Group Policy operations run under native Windows
PowerShell, after verifying on a live in-domain host that the v0.0.24 regression does not
occur over a correctly configured WinRM or SSH transport.

## Added

- `gpo_powershell_path` provider setting (default `powershell.exe`). Group Policy operations
  (`adds_backup_gpo`, `adds_json_gpo`, `adds_gpo_links`, `adds_gpo_permission`,
  `adds_gpo_security_filter`, `adds_gpo_wmi_filter` and the `adds_gpo` data source) run under
  Windows PowerShell, where the `GroupPolicy` module is native and returns non-deserialized
  objects; everything else keeps using `powershell_path` (`pwsh`). Set it to `pwsh` to force
  the compatibility layer, or to a full path if `powershell.exe` is not on `PATH`.

## Fixed

- Group Policy reads no longer lose nested object properties. Under the `pwsh` Windows
  PowerShell Compatibility layer, `Get-GPO` returns *deserialized* objects whose nested
  `.Computer.DSVersion` / `.User.DSVersion` come back null; routing these operations to native
  `powershell.exe` returns the real values.
- `adds_user` — creating a user with `enabled = true` failed with *"Provider produced
  inconsistent result after apply … .enabled: was cty.True, but now cty.False"*. New-ADUser
  always creates the account disabled because no password exists yet, so the create result
  reported `enabled = false` against a planned `true`. Create now reports the planned value;
  pair the user with a password-management resource (for example `adds_user_password`) to
  enable the account for real. Reconciling (adopt/update) a still-passwordless account with
  `enabled = true` no longer hard-fails with *"The password does not meet the length,
  complexity, or history requirement"*; enabling is deferred until a password exists, so a
  partially applied account self-heals on the next apply.
- SSH transport now enforces `timeout_seconds` on command execution. Previously the SSH runner
  ignored the context and `session.Run` had no timeout, so a remote command that never returned
  (for example a stuck `sshd`/`pwsh` session) blocked the entire apply indefinitely instead of
  failing. A hung command now returns a timeout error after `timeout_seconds`.
- SSH transport now retries transport-level failures. Win32-OpenSSH intermittently tears the
  stdin pipe down mid-command (logged on the server as *"The pipe has been ended"* in the
  PowerShellCore/Operational log), which surfaced as a failed apply even though the server was
  not under load. The runner now re-establishes the connection up to three times with
  exponential backoff on dial failures, abnormal terminations and timeouts; a clean non-zero
  exit (a real remote error) is never retried. Each retry logs a warning through Terraform's
  logger with the attempt number, backoff and underlying error, visible with `TF_LOG=DEBUG`.

## Documentation

- New guide **Connecting over WinRM and SSH** (`docs/guides/connections.md`) covering transport
  selection, WinRM basic/NTLM/Kerberos setup (including what you must supply for Kerberos and
  what the provider generates for you), SSH authentication and host-key verification, the
  observed Win32-OpenSSH stdin limitations, timeouts and how to capture logs.

## Changed

- On upgrade, GPO operations move from `pwsh` to `powershell.exe` by default (reverting the
  v0.0.25 change). This was re-validated end to end over WinRM (Kerberos) and SSH against a
  live domain controller: the gzipped bootstrap script is received and executed by
  `powershell.exe` on both transports, and `Get-GPO` returns native objects. If `powershell.exe`
  is unavailable, set `gpo_powershell_path = "pwsh"` to keep the compatibility layer.

## Internal

- Added live, host-gated transport/client tests that drive the stdin bootstrap under both
  PowerShell editions over WinRM and SSH, and assert GPO routing returns native objects
  (`internal/powershell/stdin_winrm_repro_test.go`,
  `internal/client/grouppolicy_routing_live_test.go`). They skip without `ADDS_HOST`.
- The WinRM smoke test now reads `ADDS_WINRM_KERBEROS_REALM` so it runs under Kerberos auth.
