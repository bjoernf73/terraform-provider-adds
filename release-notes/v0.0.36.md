# v0.0.36

Renames the provider to `adds` and makes remote operations substantially faster by reusing one
connection and a warm PowerShell host instead of reconnecting and re-importing the module on every
call.

## Changed

- **The provider is now `adds` (Active Directory Domain Services).** This release renames the
  fork from `adlc` throughout: the provider address is `registry.terraform.io/bjoernf73/adds`, the
  Go module is `github.com/bjoernf73/terraform-provider-adds`, every resource and data source is
  `adds_*` instead of `adlc_*`, the diagnostic event log on the target host is
  `terraform-provider-adds`, and the CI/environment variables are `ADDS_*`. To upgrade, point
  `required_providers` at `bjoernf73/adds`, rename every `adlc_*` block (and reference) to `adds_*`,
  and `terraform state mv` each existing resource to its new type, or re-import it.

- **Operations run far fewer remote processes and connections.** Each operation used to open three
  separate remote shells (stage, run, delete) over a fresh connection, and every one spawned a new
  `pwsh` that re-imported the ActiveDirectory module (~600 ms). This release:
  - collapses staging, running and deleting the script into a **single** remote process;
  - keeps **one connection alive** across operations (an SSH session per operation on a persistent
    dial; a persistent WinRM shell), so `sshd.exe` / `winrshost.exe` / `conhost.exe` stay roughly
    constant instead of accumulating hundreds of processes per apply;
  - serves default `pwsh` operations from a **warm host** — one long-lived remote `pwsh` per
    connection that keeps the ActiveDirectory module loaded, so the import is paid once per run
    rather than on every read and write;
  - skips creating the unused `AD:` PSDrive at module import (`ADPS_LoadDefaultDrive=0`), trimming
    the one import that is still paid.

  Together these roughly halve per-resource time and then cut it further. The behaviour is
  transparent: GPO operations (Windows PowerShell) and any case where the warm host cannot start
  fall back to the single-process path automatically, and a host that misbehaves is disabled for
  the rest of the run.

## Fixed

- **GPO resources no longer fail with `LdapDirectoryIdentifier` type-not-found.** The shared LDAP
  helpers use `System.DirectoryServices.Protocols`, which PowerShell 7 loads automatically but
  Windows PowerShell 5.1 (used for GPO operations such as `adds_backup_gpo`) does not. The
  assembly is now loaded on demand, so GPO imports and reads work under Windows PowerShell.

- **ACL reads and writes no longer fail with "a drive with the name 'AD' does not exist".** With
  the default `AD:` drive no longer created at import, the on-demand drive used for security
  descriptors (`adds_group` manager delegation, `adds_access_rule`) is now created in global scope
  so it outlives the helper that creates it.
