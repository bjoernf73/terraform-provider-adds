# v0.0.28

GPO version tracking is simplified to a single `version_number` watermark, and the WinRM/SSH
transport now retries transient network faults and truncated-stdin payloads instead of failing
the apply. Both changes target large, higher-latency environments where a single flaky request
or a noisy version diff would otherwise break an otherwise-clean plan.

## Changed

- **`adds_backup_gpo` and `adds_json_gpo` now track only the AD `versionNumber`.** A new
  computed `version_number` attribute is the single drift watermark (the raw packed value AD
  stores). The decoded halves remain available as the read-only `computer_ad_version` and
  `user_ad_version` for convenience, but they no longer drive drift detection. The
  `computer_sysvol_version` and `user_sysvol_version` attributes are **removed** — SYSVOL and
  AD are kept in lockstep by construction (`Import-GPO` owns SYSVOL for backup GPOs; the JSON
  import writes `GPT.ini` with the same packed version it sets on the AD object), so tracking
  SYSVOL separately added noise without signal.

  No configuration changes. Because the removed attributes were computed, existing state
  upgrades transparently: the first plan drops them and populates `version_number` on refresh.
  On the next apply a GPO may show a one-time in-place update to stamp the new watermark; this
  is expected and settles immediately.

## Fixed

- **`adds_json_gpo`: a permanent in-place update could appear after create.** The create path
  re-read `GPT.ini` through the `GroupPolicy` module immediately after writing it, which can
  return a stale `0`, so every later plan showed the version attributes flapping to
  `(known after apply)`. The import now reports the version straight from the value it just
  wrote to both the AD object and `GPT.ini`, which are equal by construction.
- **`adds_json_gpo`: a permanent diff on the GPO's `distinguished_name` (GUID casing).** The
  import returned the DN with an upper-case GUID (as Active Directory renders it) while the read
  returns it lower-case; the import now builds the DN from the lower-case GUID to match.
- **WinRM: transient network failures now retry instead of failing the apply.** A `dial tcp …:
  i/o timeout`, connection reset, refused connection, broken pipe, or TLS handshake timeout to
  the target is retried (up to three attempts, with backoff), the same way a stale-connection
  `401` already was. Previously only `401` was retried, so a single blip on a busy domain
  controller aborted the whole plan.
- **Truncated/undelivered script payloads are detected and retried.** When a WinRM `Send`
  delivers no stdin, the remote bootstrap used to run `Invoke-Expression` on an empty string and
  fail with *"Cannot bind argument to parameter 'Command' because it is an empty string"*. The
  bootstrap now detects an empty payload up front and exits with a sentinel the transport
  recognises, retrying the request (WinRM and SSH); if it still fails, the error clearly states
  the script payload was not delivered.

## Internal

- WinRM retry classification split into `isAuthFailure`, `isTransientError` (net timeouts plus a
  curated set of connection errors), and `isEmptyStdinResult`, each unit-tested
  (`internal/transport/retry_classify_test.go`). The empty-stdin sentinel is mirrored in the
  transport package to avoid a `transport -> powershell` import cycle, with guard tests on both
  sides keeping the two definitions in sync.
- `adds_json_gpo`'s read reuses `backup_gpo_read.ps1` (the reads are now identical AD-only
  reads); the separate `json_gpo_read.ps1` was removed.
