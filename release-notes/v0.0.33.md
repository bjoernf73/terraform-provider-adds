# v0.0.33

Case-only changes to names, identifiers, and text attributes are now applied instead of
being silently ignored. Previously, renaming an object or editing an attribute so that only
the letter case changed (for example `DFMA` to `dfma`) appeared to succeed but left the
directory unchanged, causing Terraform to report an inconsistent result after apply.

## Fixed

- **Case-only updates are now applied across resources.** PowerShell's `-ne`/`-eq`
  comparisons are case-insensitive, so change detection treated a case-only edit as no
  change and skipped the write. Comparisons on names and free-text/identity attributes are
  now case-sensitive:
  - `adds_group`: `name`, `sam_account_name`, and the `description`, `display_name`, `mail`,
    `info`, and `homepage` attributes.
  - `adds_user`: `name` and `user_principal_name` (on both create-time adoption and update).
  - `adds_computer`, `adds_gmsa`, `adds_organizational_unit`: `name` renames.

  Distinguished-name comparisons (moves, `managed_by`), enum values (`category`, `scope`),
  and boolean settings remain case-insensitive, as before.
